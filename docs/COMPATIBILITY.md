# Compatibility report: HCCB Lab vs. the original Microsoft Tag

**Bottom line:** HCCB Lab's *MS Tag (RE)* mode faithfully implements the 5×10 Microsoft Tag codec **as
described by one third-party reverse-engineering project (UN_HCCB)**. It has **not** been validated
against any independently sourced original Microsoft Tag image. We therefore do not claim
historical compatibility. Our encoder ↔ decoder round trips prove internal consistency only.

## 2. Evidence levels

### 2.1 Confirmed properties of the original technology (primary Microsoft source)
* Microsoft Tag derives from Microsoft Research's High Capacity Color Barcode.
* HCCB encodes data as coloured triangles in rows separated by white lines, inside a black frame.
* Smallest-capacity HCCB is readable at 3/4 inch print size; 4- and 8-colour palettes exist in HCCB generally.
* Microsoft Tag used a server-side resolver (the printed symbol is an identifier). The MSR page describes the Tag Reader app and free tag creation.

### 2.2 Established by reproducible third-party reverse engineering (UN_HCCB), checked by us for internal consistency
| Item | UN_HCCB claim | What we verified independently |
|---|---|---|
| Grid | 5 rows × 10 triangles = 50 cells | — |
| Palette | 0 yellow, 1 magenta, 2 black, 3 cyan | — |
| Payload | `CRC16-X25 (LE16) ‖ prefix (LE16) ‖ code (LE32)` = 8 bytes | CRC implementation matches the standard check value 0x906E. |
| ECC | RS over GF(32), x⁵+x²+1, 4 parity symbols, t = 2 | Their hand-written LFSR is exactly a **systematic RS(17,13) shortened code with first consecutive root α¹**. Our generic implementation reproduces their parity for 2,000 random IDs and implements a real BM/Forney decoder they lack. (UN_HCCB's own decoder never runs RS decoding; it brute-forces 1–2 colour substitutions and checks the CRC.) |
| Symbol packing | 8 bytes → 13 symbols MSB-first (1 pad bit); 4 parity symbols → 3 bytes MSB-first (4 pad bits), parity first | Reproduced. Consequence we found: the 4 parity pad bits land in **cells 8–9 and are not protected by RS**. |
| Whitening | XOR with a fixed 100-byte table (first 11 bytes used) | Table copied verbatim. **Cannot verify** its origin without the Microsoft binary. |
| Cell packing | 88 bits LSB-first per byte, two bits per cell, `cell = b0<<1 | b1` | Reproduced. |
| Trailer | cells 44–45 = [0,1] filler; 46–49 = [0,1,2,3] calibration | Reproduced. |
| Bit-exact output | — | Our Python encoder and our TypeScript port both match 50 golden vectors generated by UN_HCCB's script (`fixtures/unhccb_golden_vectors.json`). |

### 2.3 Unverified assumptions
* Whether UN_HCCB's claims match real Microsoft Tags at all. This is the main open question.
* Triangle orientation per row (col 0 pointing down in every row), and row-major cell order starting top-left.
* Exact proportions: separator thickness (11/60 of triangle height), side/top/bottom black margins (24/18/34), quiet zone (26). The heavier bottom bar is consistent with MSR samples but its ratio is not confirmed.
* Whether real tags extend the white separators through the side borders (we do, following UN_HCCB).
* Whether the original reader required the parity pad bits and filler to be exact.
* Microsoft's own orientation logic, colour calibration algorithm, and monochrome ("black-and-white Tag") variant. None of these is implemented.
* How the old server mapped `(prefix, code)` to content. HCCB Lab's resolver is a fresh design.

## 3. How to establish compatibility
1. Collect original Microsoft Tag images with known provenance (archived print ads, product packaging, Wayback Machine snapshots of tag.microsoft.com). Put them in `fixtures/historical/` with `sources.json`.
2. Run `pytest tests/test_fixtures.py`. A pass that satisfies CRC16 + RS + trailer on an original image is strong evidence (random-pass probability ≈ 10⁻⁸ per attempt).
3. If detection works but decoding fails, inspect `hccb_cli.py decode img --debug-dir out`: compare the rectified grid with the image to separate geometry errors from codec errors. Cell indices can be fed straight to `hccb.codec.decode_cells`.
4. Only after several independent originals decode correctly should the mode be relabelled "Historical HCCB Mode".
